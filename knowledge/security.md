# セキュリティ設計

## 1. 認証
Supabase Authを使用する。ユーザーIDは `auth.uid()` を基準にする。

## 2. データ分離
- 事業者データは `business_id` で分離する。
- RLSを全ユーザーデータテーブルで有効にする。
- 子テーブルは親テーブルを通じて所有権を確認する。
- クライアントから送信されたuser_idやbusiness_idを無条件に信用しない。

## 3. 秘密情報
- Supabase anon/publishable keyのみクライアントで使用する。
- `service_role` キー、DBパスワード、秘密鍵をアプリに含めない。
- `.env` はGitへコミットしない。
- `.env.example` には値ではなく変数名だけを記載する。

## 4. 会計データの保護
- 仕訳の作成・取消履歴を保持する。
- 重要な変更に監査情報を付ける。
- 添付ファイルはprivate bucketを使用し、署名付きURL等でアクセスする。
- バックアップ・復元手順を運用設計に含める。

## 5. サーバー側検証
金額、事業者所有権、仕訳貸借一致、会計期間の締め状態など、重要な検証はクライアントだけに依存しない。仕訳確定処理は信頼できるDB関数/RPCまたはサーバー側処理で行う。
